Robust Change Detection Monitoring and Alert System Using Satellite Imagery

The problem at hand is titled “Robust Change Detection Monitoring and Alert System on User-Defined AOI (Area of Interest) Using Multi-Temporal Satellite Imagery.” To put it simply, satellite imagery is captured on a daily basis through our satellites, allowing us to cover very large areas at regular intervals—say, every 5 or 10 days. This frequent coverage offers the opportunity for regular monitoring of vast land areas and enables us to detect significant changes and alert the relevant authorities in real time.

For example, in the context of ecological preservation and legal enforcement, we may need to monitor forests for deforestation, lakes for encroachment, or government-owned lands for illegal occupation. To facilitate this, we aim to develop a comprehensive system that allows users to define their own AOIs by drawing them directly on a map interface and selecting the type of changes they wish to monitor. One user might want to be alerted to deforestation events, another might want to be notified if any unauthorized construction occurs on their land, and yet another might want to monitor a water body for signs of reclamation.

Once a user defines an AOI and subscribes to specific alert types, the system will automatically gather and process relevant satellite imagery—both historical and recent—associated with that AOI. The system will handle multi-temporal analysis, meaning it compares past and current images to identify changes. The flow of information begins with AOI definition, followed by satellite data retrieval, pre-processing, change detection, and finally, alert generation.

Data processing involves steps like downloading the imagery and performing basic pre-processing. One critical step is cloud and shadow masking, as clouds can cause false positives in the detection process. These need to be removed to ensure users receive accurate alerts. The expected outcome is a fully automated change detection system that includes built-in cloud and shadow masking so that irrelevant or misleading alerts are not sent to the users.

Moreover, the system should be available as a user-friendly, web-based platform—no installation of specific software should be necessary. Users will interact through an online interface where they can define AOIs, while all data processing and analysis happen in the backend automatically. The satellite data will be downloaded from sources like Bhuvan (or other similar sources), pre-processed, and used to detect changes. For experimentation purposes, if users are unable to set up Bhuvan data pipelines, they may use Google Earth Engine (GEE) and its APIs for detection.

The maps and reports generated should be exportable in GIS-compatible formats such as GeoJSON or Shapefiles. Evaluation of the system will be based on three primary parameters:

Functionality: Users should be able to define and save multiple AOIs in their accounts. They should also be able to set thresholds for alert sensitivity based on confidence levels. For instance, a user who doesn’t want to miss any change might set a low confidence threshold (e.g., 30%), while someone who wants to avoid false positives might set a high threshold (e.g., 90%).

User Interface and Experience (UI/UX): The interface should be intuitive and easy to use, allowing non-technical users to interact effectively with the system.

Reliability: The change detection must be robust—ensuring both minimal false positives and high accuracy in detecting real changes.

Additionally, the system must be scalable and flexible, meaning its architecture should allow for the easy integration of new detection algorithms in the future. If new types of alerts or advanced algorithms are developed later, the system should be easily extendable to accommodate them.
